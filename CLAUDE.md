## Daily Data Collection

When the user says "run daily collection", execute the scheduled task:
```powershell
Start-ScheduledTask -TaskName "TFT-Coach-DailyCollect"
```
Then tail the log to show progress: `Get-Content logs\collect_$(Get-Date -Format 'yyyy-MM-dd').log -Wait`

The task runs `collect_pro.py → features.py` and logs to `logs/collect_YYYY-MM-DD.log`.

## ⚠️ CRITICAL: After Refreshing Data (Vercel deploy)

After running `features.py`, regenerate the slim CSV and push **both** files.
Vercel auto-deploys on push to `main`.

```python
# Slim CSV for hosted deploys (full match_features.csv is 335MB — over GitHub's
# limit and over Vercel's serverless bundle limit)
# MUST go in data/processed/ — that is where loadCsv() looks
python -c "
import csv
cols = ['placement','top4','level','gold_left','level_efficiency','top_trait','unit_star_avg']
inp, out = 'data/processed/match_features.csv', 'data/processed/match_features_slim.csv'
with open(inp,newline='',encoding='utf-8') as fi, open(out,'w',newline='',encoding='utf-8') as fo:
    r=csv.DictReader(fi); w=csv.DictWriter(fo,fieldnames=cols); w.writeheader()
    [w.writerow({c:row[c] for c in cols}) for row in r]
"
```

Then: `git add data/processed/match_features_slim.csv data/processed/item_winrates.csv public/dataset_info.json && git commit && git push`

⚠️ **`data/match_features_slim.csv` (root-level) does NOT exist and must never be created.** The server's `loadCsv()` always resolves paths under `data/processed/`.

⚠️ **Regenerate the slim CSV every time `features.py` runs**, or production silently
serves stale data. Local dev reads the full CSV and hosted reads the slim one, so a
missed regeneration is invisible locally. Verify they agree:

```powershell
# Row counts should match (minus 1 header line each)
python -c "import csv; [print(f, sum(1 for _ in csv.reader(open(f,newline='',encoding='utf-8')))-1) for f in ['data/processed/match_features.csv','data/processed/match_features_slim.csv']]"
```

## Architecture Overview

### Server
- `server.js` — Express on port `30002`; binds `127.0.0.1` in local dev
- On Vercel it **exports the app** instead of calling `listen()` (see the
  `process.env.VERCEL` branch at the bottom of `server.js`) — the platform invokes
  it per request
- Serves static files from `/public`
- **There is no `.env` file.** `require("dotenv").config()` runs on line 1 but
  silently no-ops; `RIOT_API_KEY`, `GEMINI_API_KEY`, and `GROQ_API_KEY` come from
  **Windows User environment variables** locally, and from Vercel project env vars
  in production. To read them locally:
  ```powershell
  'RIOT_API_KEY','GEMINI_API_KEY','GROQ_API_KEY' | ForEach-Object { "$_=$([Environment]::GetEnvironmentVariable($_,'User'))" }
  ```

### Data Pipeline (run manually to refresh data)
```
src/collect_pro.py       → scrapes Challenger/GM/Master match data via Riot API
src/features.py          → processes matches into CSV features
src/build_calculator_data.py  → fetches tactics.tools + CommunityDragon → data/static/calculator_data.json
src/build_calculator.py  → injects calculator_data.json into public/calculator.html
```

### After running `build_calculator_data.py` or `build_calculator.py`
The script writes to `data/static/calculator_data.json` and injects it into `public/calculator.html`.
**Important:** DATA injection uses string split, NOT `re.sub` — regex replacement corrupts `\n` escape sequences in JSON and breaks the JS:
```python
pre  = html.split('const DATA = ')[0]
post = html.split('const UNITS_LIST')[1]
new_html = pre + 'const DATA = ' + data_json + ';\nconst UNITS_LIST' + post
```

## Deployment (Vercel)

Live at **https://tft.tiffanygaming.com**. Auto-deploys on push to `main`.

| Thing | Value |
|-------|-------|
| Host | Vercel — project builds `toofxd/tft-coach` |
| Config | `vercel.json` — `@vercel/node`, all routes → `server.js` |
| Domain | `tft.tiffanygaming.com` → CNAME → `*.vercel-dns-017.com` |
| DNS managed at | **Google Cloud DNS** (nameservers `ns-cloud-e1..e4.googledomains.com`) — *not* Vercel, so adding a domain in Vercel does **not** auto-create the record |
| Env vars | `RIOT_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY` (set in Vercel project settings) |

The portfolio site `tiffanygaming.com` is a **separate** repo (`toofxd/tiffanygaming`,
Next.js) and a **separate** Vercel project. Two projects can serve subdomains of the
same root domain; they cannot be merged without rewriting Express as Next.js routes.

### ⚠️ `vercel.json` includeFiles
Any file read at runtime via `path.join(__dirname, ...)` is **invisible to Vercel's
bundler** and must be listed in `includeFiles`, or it will be missing from the lambda:

```
data/processed/match_features_slim.csv
data/processed/item_winrates.csv
data/processed/tactics_tools_items.json
data/static/calculator_data.json
public/**
```

These loaders have `fs.existsSync` guards, so a missing file **fails silently** —
empty results, no error. If a feature shows no data in production but works locally,
check this list first.

### Serverless constraints
- **No disk writes.** `searches.log` writes are skipped under `process.env.VERCEL`.
- **The bandit focus-area learner is disabled** — it needed persistent per-user disk
  writes. `/api/coaching` uses the static FOCUS AREAS in the prompt instead.
- **`/api/local-coach` is gated off** on hosted platforms (needs local `node:sqlite`
  access to TFTAcademy's DB).
- **Cold starts** re-parse the slim CSV and re-fetch CommunityDragon. Measured at
  0.1–0.3s in practice, but this is the first thing to check if latency regresses.

### Railway (retired)
Previously hosted on Railway; `railway.toml` is kept only for reference. The service
was removed, which is what took the site down. Nothing points at Railway now.

## Pulling More Raw Data from Riot API

### How deduplication works
`collect_pro.py` has two layers of dedup — no risk of double-counting even if re-run:
1. **Match ID dedup:** all IDs from all players are collected into a `set()` before any fetching
2. **File cache dedup:** before fetching a match, it checks if `data/raw/matches/{match_id}.json` already exists and skips it if so

So re-running the script at any time is always safe — it only fetches genuinely new matches.

### Current tiers collected
The default in `collect()` is `tiers=("challenger", "grandmaster")` — both are already included.
Current dataset (as of 11 Aug 2026):

| File | Rows | Used by |
|------|------|---------|
| `data/processed/match_features.csv` | 261,460 | local dev only (335MB, gitignored) |
| `data/processed/match_features_slim.csv` | 254,282 | **production** (committed) |
| `data/processed/item_winrates.csv` | 6,915 | both |

`public/dataset_info.json` reports `261460` / "22 June 2026" — that is the **full**
CSV count, so the About page slightly overstates what production actually loads.
The slim CSV is ~7,200 rows behind; regenerate it (see the top of this file) to close
the gap.

### To add Master tier
Edit line 84 of `src/collect_pro.py`:
```python
# Before
tiers: list[str] = ("challenger", "grandmaster"),

# After
tiers: list[str] = ("challenger", "grandmaster", "master"),
```
Master has 1,000–2,000+ players in NA. The `max_players=100` cap keeps it manageable.
Estimated time on a **dev API key**: 30–90 min (rate limited to ~50 req/min with backoff).

### To increase sample size per tier
Raise `max_players` (default 100) and/or `matches_per_player` (default 20):
```python
collect(
    tiers=("challenger", "grandmaster", "master"),
    matches_per_player=30,   # more history per player
    max_players=200,          # more players per tier
)
```
Be aware: dev keys are 100 req/2min. For large runs, expect multi-hour runtimes.
A **production API key** (applied for at developer.riotgames.com) removes this bottleneck.

### Full refresh sequence after collecting new data
```powershell
# 1. Disable sleep and hibernate first (hibernate requires elevated/admin PowerShell)
powercfg /change standby-timeout-ac 0
powercfg /hibernate off

# 2. Run collection (detached so it survives tool timeouts)
Start-Process -FilePath "python" -ArgumentList "src/collect_pro.py" -NoNewWindow -RedirectStandardOutput "collect_log.txt" -RedirectStandardError "collect_err.txt"

# 3. Monitor progress
Get-Content collect_log.txt -Tail 5

# 4. Once done, re-enable sleep and hibernate (hibernate requires admin PowerShell)
powercfg /change standby-timeout-ac 30
powercfg /hibernate on

# 5. Rebuild data and restart server
python src/features.py       # rebuild match_features.csv + item_winrates.csv
node server.js               # restart server to reload CSVs

# 6. Regenerate the slim CSV and push — otherwise production stays stale
#    (see "After Refreshing Data" at the top of this file)
git add data/processed/match_features_slim.csv data/processed/item_winrates.csv public/dataset_info.json
git commit -m "Refresh data: <N>k match features, updated item win rates"
git push                     # Vercel auto-deploys
```

⚠️ Put the **real** match count in the commit message — commit `c6f5489` shipped with
the literal placeholder `XYZk` copied from the template.

⚠️ **Do not shut down or hibernate** during collection — locking the screen is fine.
- Sleep → disabled via `powercfg` above, won't trigger automatically
- Hibernate → disable manually in **admin** PowerShell: `powercfg /hibernate off`
- Shut down / restart → kills the process, must restart collection

### Raw match files location
`data/raw/matches/*.json` — one file per match ID. Safe to inspect individually.
Do not delete these — they are the cache that prevents re-fetching.

## Known Issues & Fixes Applied

### Riot API rate limiting
`Promise.all` with 200 simultaneous match detail requests kills most with 429 silently.
**Fix:** `batchMatchDetails()` fetches in groups of 10 with 1.1s delay. `allCount` set to 50.

### Play rate > 100%
Items duplicated in combos (e.g. `[Deathblade, Deathblade, LW]`) counted twice.
**Fix:** `new Set(combo.items)` in `/api/item-recs`.

### DATA injection corruption
Using `re.sub()` to inject JSON into HTML expands `\n` sequences into real newlines → JS syntax error.
**Fix:** String split approach (see above).

### filterDrop ReferenceError
`function filterDrop(type)` — must have `autoOpen` as second param or all dropdowns break.
**Fix:** Always keep signature as `function filterDrop(type, autoOpen)`.

## Pro Dataset Integration (server.js)

All AI prompts are grounded in the Challenger/GM dataset. **Only top-4 (winning) games are used for efficiency/economy benchmarks** — losing games are excluded so the AI models what success looks like, not the average.

### Pre-computed at startup
- **`challengerBench`** — computed once from `match_features.csv` on server start:
  - `avgLevelEff`, `avgGoldLeft`, `avgLevel` → from top-4 rows only
  - `top4Rate` → winners / all rows (needs full denominator)
  - Injected into `/api/coaching` and `/api/coach` prompts as Challenger/GM reference numbers

### Per-request helpers
- **`proStats(topTrait)`** — filters `matchFeatures` to rows matching the comp's `top_trait`, then computes efficiency/gold stats from top-4 rows only. Used by `/api/coach` for comp-specific benchmarks.
- **`proUnitStats(unitId)`** — queries `itemWinrates` for the champion (min 5 games), returns top 4 item combos with actual win % and game counts. Injected into `/api/champion-tips` prompt. `top4_rate` in `itemWinrates` is already a win-rate ratio, so no filtering needed here.

### What each AI endpoint receives from the dataset
| Endpoint | AI routing | Pro data injected |
|----------|------------|-------------------|
| `/api/champion-tips` | Groq generate → Groq fact-check (2 calls) | Top 4 item combos with win % + game count from `itemWinrates` |
| `/api/coach` | `callGeminiWithSearch` → Groq fallback | Comp-specific avgLevelEff, avgGoldLeft, top4Rate (top-4 games only) + overall `challengerBench` |
| `/api/coaching` | `callGeminiWithSearch` → Groq fallback | Overall `challengerBench` (avgLevelEff, avgGoldLeft, avgLevel, top4Rate) |
| `/api/ask` | `callGeminiWithSearch` → Groq fallback | Champion roster, trait breakpoints, craftable items (see below) + live Google Search grounding via Gemini |

## Ask AI Prompt Format (`/api/ask`)

Free-form Q&A is the highest hallucination-risk endpoint — the AI is grounded two ways:

### 1. Static grounding sheets (injected into every prompt)
Built from `data/static/calculator_data.json` at server startup:
- **`champSheet`** — all 67 champions: name, cost, traits, role (one line each)
- **`traitSheet`** — all 35 traits with their valid breakpoints only (e.g. `Meeple (3/5/7/10)`)
- **`itemSheet`** — all 39 craftable items with primary stat bonuses (HP/AD/AP/armor/MR/mana regen). Raw engine variables (AS multipliers, crit, etc.) are excluded to avoid garbage in the prompt.

Traits are deduplicated by name (keep entry with most breakpoints). `Choose Trait` and traits with no breakpoints are excluded.

### 2. Live Google Search grounding (Gemini only)
`callGeminiWithSearch` adds `"tools": [{"google_search": {}}]` to the Gemini API request. Gemini automatically searches when needed (e.g. augments, patch notes, anything not in the static sheets). Billed per prompt — **5,000 free/month**, then $14/1,000.

### Fallback behavior
If Gemini fails or is rate-limited, Groq answers using only the static grounding sheets (no web search). The prompt instructs both models to flag anything not covered by the sheets as *"based on my training data, which may be outdated."*

## Champion Tips Prompt Format (`/api/champion-tips`)

The Groq prompt for champion tips enforces a specific output format — **do not change this without re-testing.**

**Best Items** section rules:
- First sentence must follow: `"[Name] benefits from [Item A] for [reason A], [Item B] for [reason B], and [Item C] for [reason C]."`
- Reasons are short (2–5 words)
- If the champion already has strong base AD/AP/survivability, the tip should note they need to cover a gap (shred, burn, wound) or stack their primary stat
- Mention **sunder/armor shred** (Last Whisper), **burn** (Sunfire Cape / Red Buff), or **grievous wounds** (Morellonomicon / Red Buff) when relevant to the champion's damage type

## UI Structure

Three pages sharing the same tab bar: **Stat Calculator**, **TFT Coach** (`public/calculator.html`), **Gods** (`public/gods.html`).

### Calculator tab (`#tab-calculator`)
- Left column: champion search, cost filter buttons (`setCostFilter` clears unit input), item/trait selectors
- Right column: stat table, item recommendations (icon grid with hover tooltips), champion tips card (`#tipsCard`)
- `selectOpt(key, unit)` → `fetchItemRecommendations(key).then(() => fetchChampionTips(unit, key))` (sequential — tips need item recs loaded first; `key` is the raw `TFT17_X` unit ID passed to the server for pro data lookup)
- `filterDrop(type, autoOpen)` — `autoOpen=false` suppresses dropdown on cost filter clicks

### Coach tab (`#tab-coach`)
- Riot ID input → `loadProfile()` → `/api/profile`
- All Set 17 stats banner (`#coachStats`) populated from `profileData.allStats`
- Recent N games banner (`#coachRecentStats`) populated from `profileData.recentStats`
- AI coaching box populated from `/api/coaching`
- Ask AI box (`#askInput`) → `/api/ask` → Gemini+Search (Groq fallback)

### Markdown formatting
`formatCoaching()` and `formatTips()` — bold blue headers from `**text:**` patterns, used for AI responses.
